
# Network Security Interview Questions 11-20 (With Detailed Answers)

## 11. What is IDS/IPS and how do they differ?
Intrusion Detection Systems (IDS) and Intrusion Prevention Systems (IPS) are security mechanisms designed to detect malicious activity within a network or host environment. An IDS monitors network traffic and logs or alerts on suspicious patterns but does not actively block traffic; it relies on signature-based, anomaly-based, or behavioral analysis detection methods. IPS, on the other hand, sits inline with network flows and can block, drop, or modify malicious traffic in real time, making it more proactive. IPS systems often integrate tightly with next‑generation firewalls to provide deep packet inspection, threat correlation, and automated policy responses. While IDS helps with visibility and forensic analysis, IPS directly mitigates attacks before they reach protected assets.

## 12. What is SSL inspection / TLS decryption?
SSL/TLS inspection is a security process where encrypted traffic is decrypted, inspected for threats, and then re-encrypted before forwarding to the destination. Modern malware and command‑and‑control traffic frequently use HTTPS encryption to evade traditional security tools, making decryption essential for visibility. Firewall or proxy devices performing TLS inspection must generate trusted certificates, manage cipher negotiation, and handle protocol versions securely. The process involves CPU-intensive operations, so hardware acceleration or offloading is often required. Proper exclusion policies are needed to avoid inspecting sensitive traffic such as banking or healthcare, ensuring compliance and user trust.

## 13. Explain what a SIEM does.
A Security Information and Event Management (SIEM) platform aggregates logs and security events from firewalls, servers, applications, and network devices into a centralized system. It correlates data to identify patterns or anomalies that may indicate ongoing attacks or compliance violations. SIEM systems use rules, machine learning, baselines, and threat intelligence feeds to provide alerts with context. They play a critical role in incident detection, response coordination, forensic analysis, and regulatory reporting. Advanced SIEMs integrate with SOAR platforms to orchestrate automated remediation, reducing mean time to respond (MTTR) during security incidents.

## 14. What is CASB and where is it used?
A Cloud Access Security Broker (CASB) acts as a control point between users and cloud applications, enforcing security policies such as authentication, data loss prevention, tokenization, and threat detection. CASBs provide visibility into sanctioned and unsanctioned SaaS usage (shadow IT), enabling organizations to assess risk and enforce governance. Depending on deployment model—API‑based, proxy‑based, or agent‑based—CASBs can apply controls like encryption, malware scanning, and session monitoring. They are essential for organizations adopting cloud‑first architectures, ensuring consistent security across Office 365, Salesforce, Google Workspace, and other SaaS platforms.

## 15. What is the role of a WAF?
A Web Application Firewall (WAF) protects web applications from attacks such as SQL injection, cross‑site scripting (XSS), file inclusion, and protocol manipulation. Unlike network firewalls, WAFs operate at Layer 7 and analyze application logic, HTTP headers, cookies, and payloads. They use rule sets, anomaly scoring, and behavioral analysis to block malicious requests while allowing legitimate traffic. Advanced WAFs provide bot mitigation, API protection, virtual patching, and DDoS shielding. By filtering web traffic and enforcing security policies, WAFs protect critical applications from exploitation and reduce the attack surface for internet-facing services.

## 16. What is SASE (Secure Access Service Edge)?
SASE is a cloud-delivered architecture that converges SD‑WAN and cloud-based security services such as secure web gateway, cloud firewall, CASB, and zero trust network access. Rather than routing traffic back to a centralized data center, SASE enforces security at distributed points of presence close to end users. This improves performance, reduces latency, and supports hybrid work environments. SASE simplifies management by unifying networking and security under one policy framework. It also enhances visibility across users, devices, and applications, ensuring consistent security regardless of location.

## 17. What is SSE and how is it different from SASE?
Security Service Edge (SSE) is the security-focused subset of the broader SASE architecture. It includes Secure Web Gateway, CASB, and Zero Trust Network Access but excludes the SD‑WAN networking component. SSE provides cloud-delivered security controls for users accessing SaaS, web, and private applications from any location. While SASE combines networking + security, SSE is purely security as a service. Organizations may adopt SSE when they already have an SD‑WAN solution in place but want to modernize their security stack with cloud-first enforcement.

## 18. What is Zero Trust Network Access (ZTNA)?
ZTNA replaces traditional VPN models by granting access based on user identity, device posture, and continuous verification instead of network location. Access is provided at the application level, not the network level, reducing lateral movement in case of compromise. ZTNA solutions dynamically verify device health, enforce MFA, and continuously evaluate trust throughout the session. Unlike VPNs that provide broad network access, ZTNA enforces least‑privilege, micro‑perimeter access. It integrates closely with IAM systems and supports hybrid cloud environments by protecting both SaaS and internal applications.

## 19. How does DNS-layer security help protect users?
DNS‑layer security blocks threats at the earliest possible stage—before connections are established—by inspecting domain queries and preventing resolution of malicious or suspicious domains. It uses threat intelligence, domain reputation scoring, and pattern analysis to identify phishing, botnet C2 domains, or malware hosts. Because DNS is universally used by all devices and applications, DNS filtering provides broad protection with minimal overhead. It is especially effective for roaming users because DNS requests can be forced to cloud resolvers that enforce enterprise security policies. This approach complements firewalls and endpoint protection by adding another preventive layer.

## 20. Explain cloud-first vs on-prem security models.
In a cloud-first security model, inspection and policy enforcement happen in distributed cloud security nodes instead of centralized firewalls. Traffic is routed directly to the internet (local breakout) for SaaS access, improving performance and reducing backhaul delays. Cloud-first models support scalable, elastic security, ideal for remote work and global deployments. On-prem security models rely on physical firewalls or appliances installed in data centers, providing strong perimeter defense but requiring more complex management for distributed environments. Organizations increasingly adopt hybrid approaches, using cloud-based SSE/SASE while retaining on-prem firewalls for internal data center workloads.
